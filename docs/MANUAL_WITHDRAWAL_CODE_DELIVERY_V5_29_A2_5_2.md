# V5.29.A2.5.2 — Manual Withdrawal Code Delivery

## Status

Implemented locally. Browser acceptance required.

## Corrected operating model

Withdrawal verification codes are generated by an administrator but are **not automatically delivered**.

Flow:

1. Customer submits withdrawal request.
2. Admin generates a one-time code.
3. Full code is shown to that admin once.
4. Admin copies the code.
5. Admin opens the customer's private dashboard notice composer.
6. Admin pastes the code and deliberately sends the notice.
7. The sent notice is linked back to the withdrawal request for audit/tracking.
8. Admin may regenerate or destroy the request/code when needed.
9. Customer verifies the code and submits payout details.
10. Pending payout is created and resolved through Approve / Reject.

## Security

Only the hash and last four digits are persisted on the withdrawal request. The full code is not stored for later display. If the administrator loses the displayed code, a new code must be generated.

## UI

Withdrawal Requests and Direct Dashboard Notices now use the current compact Rcentz admin workspace language rather than the older table/template presentation.
